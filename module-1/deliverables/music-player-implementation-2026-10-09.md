# Плеер и первый экран статьи — 9 октября 2026

> Архив первоначального варианта. По последующему запросу пользователя интерфейс переведён на официальный виджет Яндекс Музыки и прежние тестовые релизы КИНО. Kevin MacLeod больше не отображается; его MP3 не включаются в сборку. Текущий плеер — `src/media-yandex-player.js`.

На `about.html`, где находилась заглушка «ТУТ БУДЕТ ЛЕНДИНГ», добавлены три подборки по настроению и четыре записи. `article.html` воспроизводит первый экран [Figma 221:1173](https://www.figma.com/design/r9ZKy9SrKAYfBTndGQpbct/%D0%9B%D0%B5%D1%88%D0%B0?node-id=221-1173). Под первым экраном размещён блок «Звук для чтения». Полный редакционный текст не был предоставлен; вместо выдуманного материала стоит отметка «Статья в работе».

Автор всех четырёх записей — **Kevin MacLeod**. Проверены страницы конкретных записей, актуальный JSON каталога автора и [его FAQ](https://incompetech.com/music/royalty-free/faq.html). [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/deed.en) допускает коммерческое использование и распространение с сохранением атрибуции. CC BY-NC для этого прототипа не используется.

Файлы скачаны непосредственно с сайта автора, сохранены без изменения. В `assets/audio/manifest.json` указаны исходная страница, адрес загрузки, ISRC, дата проверки, размер и SHA-256 каждого файла. `assets/audio/LICENSE.txt` содержит атрибуцию. В интерфейсе авторство доступно через «Авторы и лицензии» и раскрытие нижнего плеера; название, автор, источник и ссылка на лицензию присутствуют. На статье явно указано, что эта подборка не является музыкой madk1d.

Снимки авторского FAQ и шаблона страницы, а также выбранные записи из JSON сохранены в `deliverables/music-license-evidence/`. Это внутренняя проверочная документация; сборка сайта её не публикует. Тест сверяет реальные MP3 с зафиксированными хешами, но не заменяет проверку прав на новые записи.

Scott Buckley рассматривался как дополнительный источник, однако [его условия](https://www.scottbuckley.com.au/library/using-this-music/) требуют синхронизации с другим медиа и отдельно ограничивают распространение через музыкальные стриминговые платформы. В этот плеер его записи не включены.

## Подключение без музыкального сервиса

Внешний API не требуется: один HTML `<audio>` воспроизводит локальные MP3 через [HTMLMediaElement API](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement). Метаданные и подборки заданы в `src/music-library.js`. Публичный `pieces.json` Incompetech использован для проверки записей при подготовке; сайт не зависит от него во время работы, и он не представлен как гарантированный API сервиса.

Такой способ не требует ключей Яндекс Музыки, Spotify или SoundCloud. Основание для использования файлов — лицензия автора, а не наличие API. Добавляя музыку других исполнителей, сначала проверьте права на саму композицию, запись, исполнение и включённые сэмплы; свободная лицензия одного файла не открывает весь каталог артиста.

## Поведение

- Play / pause, выбор трека и настроения, следующая/предыдущая запись, перемотка ползунком и на ±30 секунд, громкость, отключение звука, очередь, закрытие с остановкой.
- На телефоне компактный режим оставляет Play, позицию, раскрытие очереди и закрытие; трек можно сменить в очереди. Громкость регулируется системными кнопками телефона.
- Автопереход внутри выбранной подборки включён по умолчанию, его можно выключить. В конце подборки воспроизведение останавливается.
- Переходы через ссылки между `about.html` и `article.html`, включая Back/Forward, заменяют только содержимое страницы. Элемент аудио сохраняется и звук не прерывается. Переход на старую главную, открытие новой вкладки или полная перезагрузка создают новый документ.
- При перезагрузке выбранный трек и позиция восстанавливаются без автоматического запуска. Последняя позиция сохраняется раз в пять секунд и при уходе со страницы. Заблокированный localStorage не мешает прослушиванию.
- До нажатия Play аудиофайлы не загружаются. При ошибке виден текст и доступна ссылка на оригинальный источник. Повторный Play повторяет запрос.
- [Media Session API](https://developer.mozilla.org/en-US/docs/Web/API/Media_Session_API) добавляет название/автора и системное управление там, где браузер поддерживает эти действия. Проверено в Chrome; поведение фонового воспроизведения на физических iPhone/Android отдельно не проверялось.

## Вёрстка и проверки

Первый экран статьи на ширине 1920 px имеет размер 1920 × 880, как в Figma. Фото, звезда и обе стрелки выгружены из указанного узла; временных Figma URL в коде нет. Используются существующие Benzin ExtraBold и Giga Sans. Мобильная компоновка адаптирована самостоятельно, так как отдельный мобильный макет в запросе не предоставлен.

Проверки: 27 тестов `npm test`, успешный `npm run build`, реальное воспроизведение MP3 в Chrome, сохранение одного audio при переходах, перемотка, громкость, окончание/смена записи, выключение очереди, восстановление без autoplay и остановка при закрытии. Проверены 320, 375, 768, 1280 и 1920 px, загрузка изображений, отсутствие горизонтального скролла и ошибок JS. Детали — `deliverables/music-browser-validation.json`; рядом сохранены превью.

Dev-сервер поддерживает MIME `audio/mpeg` и HTTP byte ranges для перемотки. На хостинге также нужны корректный MIME и ответы `206 Partial Content` на Range-запросы. Общий размер четырёх исходных MP3 — около 35.7 MiB. Перекодирование не делалось; при будущем сжатии нужно отразить изменение в атрибуции и обновить хеши.

Запуск: `npm run dev`, затем `http://localhost:4173/about.html` или `http://localhost:4173/article.html`. Публикация на внешнем хостинге в этой задаче не выполнялась.
